# Architecture and provider setup

## Translation pipeline

A classic extension loader constructs `platform/extension.js` and calls `content/main.js: start(platform)`. The userscript entry constructs `platform/userscript.js` and calls the same entry point. Content modules depend on the supplied platform for storage, translation, language detection, commands and settings; they do not read Chrome or GM globals.

The extension declares no static content scripts. `background/injection.js` ensures a ready top controller before toolbar/shortcut/menu commands, using activeTab and scripting; a per-tab task and isolated-world loader Promise prevent duplicate startup. Content CSS is inserted through scripting, without adding a DOM style node. `background/permissions.js` serializes registration decisions after settings/permission changes: broad optional access plus a passive feature or automatic rule registers loader/CSS for future documents and frames. Revocation saves dependent settings as off, unregisters owned scripts, and stores a local notice field list for popup UI. Canvas hooks and CDN DNR rules independently check their host grants. Fixed required hosts cover translation providers only; custom APIs use optional origin grants. See SPEC for the tab-ensure and revocation contracts.

The walker finds visible paragraph units and serializes inline formatting as bounded placeholders. IntersectionObserver schedules nearby units; idle slices spread scanning/insertion across frames. MutationObserver and navigation events handle updates. The injector restores only validated original formatting and safely inserts text; model output never reaches executable markup. PDF coordinate segmentation keeps numbered table-of-contents leader rows separate, preserving row alignment and batch cardinality while math remains opaque.

Automatic source language stays automatic at the translation service. Browser language guesses filter already-target-language text but do not force a possibly incorrect or unsupported source code into provider requests. The existing script-based Japanese hint and explicit user source selections remain intact.

Muted translation text mixes 78 percent of the source colour with the measured background only when contrast remains at least 4.5:1. Otherwise it uses the source colour if that is readable, then the higher-contrast black or white endpoint. A page's already-low-contrast metadata must not become unreadable translation text. This changes only the inserted translation, never the original page colour.

The v0.4 layout pass preserves headlines, article links and long source text. Short controls try inline bilingual output before measured overflow can permit replacement. Headline clipping is released through shared style claims and restored exactly. Sibling structures share presentation decisions; HN metadata uses one compact sentence with complete time phrases. Public identifier checks precede serialization, and a small Chinese UI glossary answers common English labels locally without provider requests. Boundary identifiers stay outside source ranges. Automatic page/PDF refinement filters out UI and short units before the LLM queue; unparseable model content advances the chain, and refinement finals wait for complete response validation.

On the extension, translation uses runtime ports and the background service worker, with fetch and IndexedDB caching. On the userscript, the same providers, queue, translator and handlers run in the userscript sandbox, with injected anonymous `GM_xmlhttpRequest` transport and a timestamp-evicted memory/GM cache capped at 2 MB. Neither translations nor keys enter the site's localStorage or IndexedDB. Both providers and translator resolve keys through injected `getSecret(id)` at request time; public settings are not hydrated with keys.

The extension remains zero-build. `scripts/build_userscript.mjs` uses only Node standard-library modules to bundle the static module graph and CSS into a scoped IIFE. Token-checked gap compaction retains ASI-sensitive newlines and separated operators; a shared helper preserves export getters. The build enforces a 345000-byte startup budget. QR/PDF/desktop sidebar entry modules remain excluded; mobile OCR/comic and shared text/subtitle tools remain available. Unsupported module syntax fails the build. The generated `duallens.user.js` is a release asset covered by SHA256SUMS; bookmarklet delivery remains planned.

The v0.4 engine adds injected `createMT` adapters beside the existing LLM pipeline. `mt+llm` checks the LLM cache first, then runs both stages for misses when `draft:true` is requested. Drafts leave ids open through the content client, extension port and GM platform; only finals/errors close them. The same `dl-t` receives the refinement, with no loading spinner replacing readable text. A refinement timeout cancels LLM work and retains MT quietly. Different text lengths can still change paragraph height. Legacy consumers without draft support receive one terminal result, with MT as failure/timeout fallback. PDF callers must opt into drafts and handle repeated ids.

Microsoft and Google free adapters use unofficial batch endpoints; Microsoft can additionally try a short-lived token flow on 401/403. They may change, throttle or fail without notice. Official Azure/DeepL adapters resolve local secrets at request time. MT sends only serialized text/placeholder tags and languages, never page HTML attributes, title, URL or cookies. HTML/XML placeholder output is validated or safely reduced to plain text. Oversized groups are sent as bounded plain pieces. MT cache keys include engine and language pair; LLM cache keys remain separate. Runtime HTTP slots limit MT concurrency across requests (3 desktop, 2 coarse-pointer userscript), and partial omissions try another engine only for missing items.

The interface contracts are [SPEC.md](SPEC.md) and [PLATFORMS.md](PLATFORMS.md). [ROADMAP.md](ROADMAP.md) separates implemented features from planned work.

The iframe increment shares a `FrameRoots` lifecycle between the extension and userscript. Same-origin HTML documents receive temporary content CSS, mutation/retry/scroll listeners and range-based scheduling through the owning controller. Load, mutation and resize events detect navigation and same-Document body replacement without root polling; removal cancels ownership and restores existing units. Cross-origin extension documents load only a UI-free frame agent, and readable-parent documents decline ownership. The worker forwards each browser-identified child request only to frameId:0 in its own tab. Each child asks once at startup; top-only state publishers broadcast changes to child consumers in their own tab. Local intersection/resize/visibility events govern visibility without background calls or visibility leases. Open ShadowRoots share the same root registry, CSS lifecycle and mutation/scroll watchers; assigned slot text stays with its light DOM source and closed roots are skipped. Top-level public settings/context and active state govern proxies; no page message bridge or new permission is used. Userscripts stay top-frame-only and cannot enter cross-origin frames. Static bundling omits unconsumed export getters while preserving module bodies, side effects and namespace/live bindings to keep the iframe increment inside the 345000-byte budget.

The desktop PDF reader keeps equal-size original/translated sheets, with original-only, translated-only and reflow views. A local module Worker groups PDF text coordinates into paragraphs, columns and separate TOC rows. Only visible and adjacent pages request text translation through the injected TranslatorService; PDF bytes, image crops, URLs and metadata stay local. Translated sheets copy the original rendering and cover prose line rectangles with sampled background colors, then fit safely created text nodes into the original block. Math-heavy blocks, running margins and rotated/RTL content retain original pixels; inline math atoms become local canvas crops. Missing or invalid atoms retain the source or a validated draft. Rendering retains at most five page pairs and slices color sampling and overlay insertion. PdfTranslations accepts draft/final updates and isolates each request attempt so restore, retry and page release cannot receive stale results. This consumer is ready for staged engine replies; the shared transport must also forward the optional draft/purpose/stage fields. See [PDF.md](PDF.md) for limits and separate mock/live acceptance.

Malformed JSON cardinality and exhausted content-omission fallbacks retry unfinished half batches, then individual items, sharing at most eight additional requests per original batch. Incorrect array positions are never guessed; single-item failure or budget exhaustion remains an explicit error. A range-aware lazy observer schedules individual source spans inside tall reader hosts and rechecks pending ranges on scrolling. Japanese prose echoes are checked before streamed display; this heuristic is not a translation-quality guarantee.

The transport accepts optional `http.onText(delta,status,headers)`, using fetch streams or GM progress and returning the complete response text. Providers accept `onDelta(text)` and decode only redacted SSE content, with an idle timeout reset by content/reasoning progress. Complete translation items render early; only validated final batches enter the cache. A retained proper name in a complete JSON batch does not discard neighboring validated translations. Content omissions skip a model only for that job; they do not globally cool a working provider. Cancellation removes pending and late results.

Comic site entries accept optional `imageHosts` and same-site root `referer` metadata. Session DNR rules modify only extension-initiated XHR/other requests to those CDN domains; website image requests do not match. Registry updates serialize, preserve unrelated rule IDs, and remove owned rules when comics are disabled or the site is removed. GM image downloads use the same policy with an explicit Referer header and retain the existing failure/capability degradation.

## Settings and shared UI

Content translation services are wrapped by `content/confirmation.js` before page, interaction,
subtitle and comic consumers receive them. It checks the device-state destination contract, serializes
confirmation cards and rechecks destinations before dispatch. Batch cancellation aborts a waiting card;
legacy transports without `done` finish only after terminal results. The extension and userscript use
the same closed-shadow card and device-local acknowledgements. OCR recognition separately checks
installed language packs before requesting download confirmation; concurrent images share the prompt
for a language. The owning page controller supplies `onDecline` on the guarded facade so dismissal
stops queued page batches as well as the current request.

Every platform uses `createSettingsStore({ syncArea, localArea })`. On the extension both areas use the common Chrome adapters from `shared/storage-areas.js`; quota/unavailable fallback belongs to the shared store, not a second platform wrapper. Nonsecret settings are split across `settings.core`, `settings.glossary` and `settings.sites`. API keys stay in local `secrets`; the local compatibility mirror is key-free. New installations have no selected provider and make no automatic model requests.

The userscript uses a single GM private record for both areas. GM storage is local per script/manager; it is not cloud sync. Transitional GM public settings are migrated once, preserving an existing versioned configuration and newer local secrets. Encrypted configuration export/import is the explicit device-transfer path; plaintext exports omit secrets. Other devices need their own keys unless the user intentionally imports an encrypted backup.

`onChange` invalidates settings rather than sending a snapshot. Content reloads through the store, ignores stale loads, and compares objects independently of property order. This prevents a storage reordering/migration from canceling an in-progress hover translation. Actual changes to language, provider chain, prompts, terms and selectors invalidate old translations; style, display mode and interaction settings update in place where appropriate.

Options and the userscript panel share `ui/forms/index.js: mountSettingsForm`. In v0.5, only extension options import it directly. The packer emits a separate `duallens-settings.js` IIFE resource with explicit entry exports; the userscript metadata pins its versioned release URL and SHA-256. Opening a userscript popup, settings or text/subtitle tool reads the manager's cached resource, checks byte length and SHA-256 locally (including an HTTP fallback), then evaluates the verified code inside the sandbox. No page-global export, DOM script or runtime network fetch is used. Missing/corrupt/unexecutable resources show reinstall guidance in the browser UI language. The startup target is 345000 bytes. The panel retains the `mountForm` seam and calls `destroy()` when closed, including a close that races asynchronous mounting. The userscript provides `promptSecret(label)`, using the native prompt binding captured in its isolated DOM sandbox before asynchronous boot. API keys and backup passphrases never have page-DOM input fields; the form shows only key presence and set/clear buttons. Prompt defaults are empty, cancellation preserves drafts, and Save persists changes. Extension options retain ordinary password fields on their own extension origin; the extension platform's prompt method returns null.

QR export is an optional `platform.renderQr(canvas, text)` capability supplied only by extension options. Shared forms fall back to copyable encrypted text, so neither the QR encoder nor desktop PDF/side-panel entry modules enter the userscript startup bundle. The common popup/settings/text/subtitle tabs load from the verified lazy resource; its startup limit is 345000 bytes. Subtitle preferences belong to the shared nonsecret schema and survive compact/full configuration imports. The packer assigns deterministic numeric module ids and short reserved factory bindings, retaining a module-path audit comment and live export getters. The stricter 345000-byte working budget remains enforced without removing mobile features.

Closed shadow roots and bullet rendering do not isolate composed keyboard, input or paste events from a hostile page. The former Proxy input adapter has been removed. An isolated-world regression loads the unchanged bundle after poisoning the host page's prompt and installing document event listeners; native dialog entry must still save the key without reaching those hooks. Actual Tampermonkey sandbox behavior still needs real-device acceptance.

On coarse-pointer devices hover becomes a cancellable 500 ms paragraph hold. Runtime limits cap batches at 12 items, concurrency at 2 and lazy margin at 400 px without changing saved values. Selection controls appear below the selected text; the draggable floating ball also offers translation of the last focused input. Narrow settings panels use the full viewport and safe-area padding. Synthetic Chromium touch checks are distinct from real Android Edge/Tampermonkey acceptance.

## Providers and release state

Direct OpenAI-compatible services use user-supplied addresses, models and local API keys. Presets cover OpenAI, DeepSeek, OpenRouter (including public free-model discovery), Ollama, LM Studio and custom services. Local URLs refer to the current device; Ollama requires `OLLAMA_ORIGINS` for the extension origin. The offline mock requires no account or network. Generic 429/Retry-After backoff, per-profile/model cooldown and cross-service fallback remain shared.

Settings v3 converts a legacy `gateway` profile kind to `openai` without changing its id, endpoint, model, limits or chain references. The same local secrets slot supplies its Bearer key. The transition disables floatBall/selection/hover/input/comics once; later opt-ins survive reloads and encrypted device transfer. New installs start with these enhancements off and no automatic site rules.

The manifest public key only stabilizes the unpacked extension ID; no private signing key is distributed. Store packaging removes this field. Browser settings/cache live in the current browser profile or manager-private storage. Development environments and raw artifacts stay outside the checkout; E2E output is configurable with `DUALLENS_E2E_OUT`, defaulting to a system temporary directory. Release packaging runs the public-file privacy gate before writing deterministic archives.

The v1 integration resource entry is userscript/ui-resource.js. Popup/onboarding/upgrade UI and all shared forms/media panels are absent from the startup module graph. Lightweight menu registration loads the same byte/SHA-256-verified cached resource on demand. Top-frame consent publishes confirmed destination IDs to UI-free frame agents; sidebar text/subtitle file tools render the same gate inline. PDF toolbar actions capture bounded anonymous bytes while activeTab access applies, store them briefly in extension IndexedDB, and open a one-use token reader that consumes/deletes bytes and removes the token from its URL. Direct external reader sources instead request their origin in a user gesture.
