# Architecture and provider setup

## Translation pipeline

A classic extension loader constructs `platform/extension.js` and calls `content/main.js: start(platform)`. The userscript entry constructs `platform/userscript.js` and calls the same entry point. Content modules depend on the supplied platform for storage, translation, language detection, commands and settings; they do not read Chrome or GM globals.

The walker finds visible paragraph units and serializes inline formatting as bounded placeholders. IntersectionObserver schedules nearby units; idle slices spread scanning/insertion across frames. MutationObserver and navigation events handle updates. The injector restores only validated original formatting and safely inserts text; model output never reaches executable markup. PDF coordinate segmentation keeps numbered table-of-contents leader rows separate, preserving row alignment and batch cardinality while math remains opaque.

On the extension, translation uses runtime ports and the background service worker, with fetch and IndexedDB caching. On the userscript, the same providers, queue, translator and handlers run in the userscript sandbox, with injected anonymous `GM_xmlhttpRequest` transport and a timestamp-evicted memory/GM cache capped at 2 MB. Neither translations nor keys enter the site's localStorage or IndexedDB. Both providers and translator resolve keys through injected `getSecret(id)` at request time; public settings are not hydrated with keys.

The extension remains zero-build. `scripts/build_userscript.mjs` uses only Node standard-library modules to bundle the static module graph and CSS into a scoped IIFE. Token-preserving comment/indentation removal keeps the startup bundle below 400000 bytes and retains line terminators for automatic semicolon insertion. Unsupported module syntax fails the build. The generated `duallens.user.js` is a release asset covered by SHA256SUMS; bookmarklet delivery remains planned.

The v0.4 engine adds injected `createMT` adapters beside the existing LLM pipeline. `mt+llm` checks the LLM cache first, then runs both stages for misses when `draft:true` is requested. Drafts leave ids open through the content client, extension port and GM platform; only finals/errors close them. The same `dl-t` receives the refinement, with no loading spinner replacing readable text. A refinement timeout cancels LLM work and retains MT quietly. Different text lengths can still change paragraph height. Legacy consumers without draft support receive one terminal result, with MT as failure/timeout fallback. PDF callers must opt into drafts and handle repeated ids.

Microsoft and Google free adapters use unofficial batch endpoints; Microsoft can additionally try a short-lived token flow on 401/403. They may change, throttle or fail without notice. Official Azure/DeepL adapters resolve local secrets at request time. MT sends only serialized text/placeholder tags and languages, never page HTML attributes, title, URL or cookies. HTML/XML placeholder output is validated or safely reduced to plain text. Oversized groups are sent as bounded plain pieces. MT cache keys include engine and language pair; LLM cache keys remain separate. Runtime HTTP slots limit MT concurrency across requests (3 desktop, 2 coarse-pointer userscript), and partial omissions try another engine only for missing items.

The interface contracts are [SPEC.md](SPEC.md) and [PLATFORMS.md](PLATFORMS.md). [ROADMAP.md](ROADMAP.md) separates implemented features from planned work.

The desktop PDF reader keeps equal-size original/translated sheets, with original-only, translated-only and reflow views. A local module Worker groups PDF text coordinates into paragraphs, columns and separate TOC rows. Only visible and adjacent pages request text translation through the injected TranslatorService; PDF bytes, image crops, URLs and metadata stay local. Translated sheets copy the original rendering and cover prose line rectangles with sampled background colors, then fit safely created text nodes into the original block. Math-heavy blocks, running margins and rotated/RTL content retain original pixels; inline math atoms become local canvas crops. Missing or invalid atoms retain the source or a validated draft. Rendering retains at most five page pairs and slices color sampling and overlay insertion. PdfTranslations accepts draft/final updates and isolates each request attempt so restore, retry and page release cannot receive stale results. This consumer is ready for staged engine replies; the shared transport must also forward the optional draft/purpose/stage fields. See [PDF.md](PDF.md) for limits and separate mock/live acceptance.

Malformed JSON cardinality and exhausted content-omission fallbacks retry unfinished half batches, then individual items, sharing at most eight additional requests per original batch. Incorrect array positions are never guessed; single-item failure or budget exhaustion remains an explicit error. A range-aware lazy observer schedules individual source spans inside tall reader hosts and rechecks pending ranges on scrolling. Japanese prose echoes are checked before streamed display; this heuristic is not a translation-quality guarantee.

The transport accepts optional `http.onText(delta,status,headers)`, using fetch streams or GM progress and returning the complete response text. Providers accept `onDelta(text)` and decode only redacted SSE content, with an idle timeout reset by content/reasoning progress. Complete translation items render early; only validated final batches enter the cache. A retained proper name in a complete JSON batch does not discard neighboring validated translations. Content omissions skip a model only for that job; they do not globally cool a working provider. Cancellation removes pending and late results. The optional gateway forwards OpenAI SSE, preserves errors before headers, and wraps a final JSON reply when upstream streaming is unsupported. A post-header failure has an error event without `[DONE]`.

Comic site entries accept optional `imageHosts` and same-site root `referer` metadata. Session DNR rules modify only extension-initiated XHR/other requests to those CDN domains; website image requests do not match. Registry updates serialize, preserve unrelated rule IDs, and remove owned rules when comics are disabled or the site is removed. GM image downloads use the same policy with an explicit Referer header and retain the existing failure/capability degradation.

## Settings and shared UI

Every platform uses `createSettingsStore({ syncArea, localArea })`. On the extension both areas use the common Chrome adapters from `shared/storage-areas.js`; quota/unavailable fallback belongs to the v2 store, not a second platform wrapper. Nonsecret settings are split across `settings.core`, `settings.glossary` and `settings.sites`. API keys stay in local `secrets`; the local compatibility mirror is key-free. New installations have no selected provider and make no automatic model requests.

The userscript uses a single GM private record for both areas. GM storage is local per script/manager; it is not cloud sync. Transitional GM public settings are migrated once, preserving an existing v2 configuration and newer local secrets. Encrypted configuration export/import is the explicit device-transfer path; plaintext exports omit secrets. Other devices need their own keys unless the user intentionally imports an encrypted backup.

`onChange` invalidates settings rather than sending a snapshot. Content reloads through the store, ignores stale loads, and compares objects independently of property order. This prevents a storage reordering/migration from canceling an in-progress hover translation. Actual changes to language, provider chain, prompts, terms and selectors invalidate old translations; style, display mode and interaction settings update in place where appropriate.

Options and the userscript panel share `ui/forms/index.js: mountSettingsForm`. The panel retains the `mountForm` seam and calls `destroy()` when closed, including a close that races asynchronous mounting. The userscript provides `promptSecret(label)`, using the native prompt binding captured in its isolated DOM sandbox before asynchronous boot. API keys and backup passphrases never have page-DOM input fields; the form shows only key presence and set/clear buttons. Prompt defaults are empty, cancellation preserves drafts, and Save persists changes. Extension options retain ordinary password fields on their own extension origin; the extension platform's prompt method returns null.

QR export is an optional `platform.renderQr(canvas, text)` capability supplied only by extension options. Shared forms fall back to copyable encrypted text, so neither the QR encoder nor desktop PDF/side-panel entry modules enter the userscript startup bundle. The common text/subtitle tabs remain in the mobile bundle; its 400000-byte limit is unchanged. Subtitle preferences belong to the shared nonsecret schema and survive compact/full configuration imports.

Closed shadow roots and bullet rendering do not isolate composed keyboard, input or paste events from a hostile page. The former Proxy input adapter has been removed. An isolated-world regression loads the unchanged bundle after poisoning the host page's prompt and installing document event listeners; native dialog entry must still save the key without reaching those hooks. Actual Tampermonkey sandbox behavior still needs real-device acceptance.

On coarse-pointer devices hover becomes a cancellable 500 ms paragraph hold. Runtime limits cap batches at 12 items, concurrency at 2 and lazy margin at 400 px without changing saved values. Selection controls appear below the selected text; the draggable floating ball also offers translation of the last focused input. Narrow settings panels use the full viewport and safe-area padding. Synthetic Chromium touch checks are distinct from real Android Edge/Tampermonkey acceptance.

## Providers

1. **Direct OpenAI-compatible profile**: configured by the user, supports SSE chat completions with non-streaming fallback. Presets include OpenRouter, DeepSeek, SiliconFlow, Zhipu, Moonshot, OpenAI, Gemini, Groq, SJTU and Ollama/custom endpoints. OpenRouter is the recommended first example: explicit model discovery filters zero input/output pricing and proposes a diverse free-model chain. An unconfigured LLM profile cannot refine, but the default mode can translate through MT without a key.
2. **Mock**: offline deterministic prefix, used for tests and interaction demos.
3. **Optional local gateway**: Python standard library, http://127.0.0.1:18790/v1. Default enabled backend is Ollama; other integrations require explicit config. Direct remote services work on every supported device without this service.
4. **Machine translation**: Microsoft → Google free unofficial endpoints by default, or user-selected official Azure/DeepL APIs. Modes are `mt`, `llm`, `mt+llm` (default) and LLM-first `auto` (MT after 2.5 seconds). Selection/hover/input prefer MT in mixed modes; selection may explicitly request LLM refinement. New installs have no selected LLM; translation is user-triggered and requires no local gateway. Official MT keys use `mt-microsoft-api` / `mt-deepl` secret ids, with encrypted transfer and no public export.

`provider.chain = [{ profileId, model }, …]` can span profiles and endpoints. Cooldown is scoped to profile plus model. 404/429/502/503/network failures immediately try the next non-cooling candidate; a busy provider merely queues work. Actual fallback identity participates in cache keys. Subscription CLI models remain explicit-only. Free-model fallback cannot bypass an account's daily/minute quotas or guarantee availability.

Hermes discovery intersects the proxy catalog and configured free-model allowlist. An actual 404 hides the model for 30 minutes; catalog discovery itself makes no completion calls and cannot prove provider availability. One-click gateway setup uses only that discovered catalog, while a fresh gateway profile still defaults to Ollama without automatic fallback.

Optional config is ~/.duallens/gateway.json, merged over defaults. The [example](../gateway/gateway.example.json) contains no credentials. Backend model lists are explicit allowlists. For custom Ollama models, change ollama.models and choose the corresponding ollama/<model> identifier in extension settings.

## Optional integrations

- **SJTU** adapts an already configured DDL Hub relay at 127.0.0.1:18765. It checks /ledger before background calls and reads proxy_token from the existing ~/.ddl-hub/config.json in memory. DDL Hub and credentials are not part of this release. Leave the backend disabled if that service does not exist.
- **Hermes** adapts an existing independent hermes proxy at 127.0.0.1:8645. The model allowlist must remain limited to the free models you intend to use. Authentication belongs to Hermes. No chat-agent configuration or messages are changed.
- **Claude/Codex** are opt-in Windows npm CLI adapters using existing official login state. The gateway does not create accounts, API keys or OAuth state. Model/account limits remain provider-controlled; daily_limit=0 means no additional gateway cap. Translation child processes use stdin and temporary empty directories, have tools disabled, and receive no API-key billing environment variables.

To enable a backend, set its enabled field to true in machine-local config and restart your gateway. Use settings to choose its model explicitly; optional fallback models should be added intentionally. Configuration never belongs in this repository.

## Release identity and state

The manifest contains a public key used only to make the unpacked extension ID stable. The gateway derives its default Origin allowlist from that public key. A complete source/runtime bundle includes extension/ alongside gateway/ so this identity can be read. For the store build, add the store-assigned extension ID to the explicit allowlist on each machine; only exact `chrome-extension://<id>` entries are accepted. No private signing key is distributed.

Gateway usage, metadata and config live under ~/.duallens. Browser settings/cache live in the current browser profile. Development dependencies, test profiles and raw artifacts stay outside the source tree. GitHub contains reproducible source and tagged release assets, not machine state.
