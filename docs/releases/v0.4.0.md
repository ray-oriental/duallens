# DualLens v0.4.0 — 机器翻译秒出 + 大模型精修，整页覆盖与版式保持 PDF

开箱即可翻译：没有任何模型配置时使用免费机器翻译；配置了大模型（自己的服务或可选的本机网关）后，先显示机器翻译草稿，再由大模型原位精修。扩展保持零构建，用户脚本 356,581 字节（新的启动预算 360,000 字节）。

## 双引擎
- 新增 `translation.mode`：`mt`（仅机器翻译）/ `llm`（仅大模型）/ `mt+llm`（默认）/ `auto`。机器翻译默认用微软 Edge 免费接口，失败换 Google 免费接口；两者都是非官方用法，可能变动，设置页可单独测试。
- `mt+llm`：草稿 `stage:'draft'` 先出现，大模型终稿在同一位置替换，不跳版式；大模型失败或超时就静默保留草稿。只有正文类单元（≥ 6 个词或 ≥ 12 个 CJK 字）送大模型，导航、按钮、元信息直接用机器翻译或内置 UI 词表，请求量大幅下降。
- 模型返回非 JSON（例如思考型模型把思考过程当正文）计为该模型失败并换下一个；「测试连接」改为真实的两项翻译探针。
- 隐私：默认的机器翻译会把页面文字发给微软（失败时发给 Google）。可在站点规则中排除，或改用 `llm` 模式。详见 [隐私说明](../PRIVACY.md)。

## 整页覆盖与双语排版
- 导航、按钮、标签、表头、表单标签与 `placeholder`、图片说明、页脚、评论和动态加载内容都会翻译；代码、公式、URL、数字、用户名、文件/分支名、话题标签和作者/频道名保持原文。
- 按容器选择呈现方式：正文块级对照；短文本行内紧凑；只有放不下的小控件才只显示译文（原文在悬停提示里）。标题和长文本始终保留原文；同类兄弟元素使用同一种呈现方式。
- 元信息行（如 Hacker News 的积分/作者/时间行）合成一条紧凑译文；暗色站点按实际前景/背景计算译文颜色。
- 首屏优先调度：在 18+ 类真实网页上首段译文通常在 0.1–1 秒内出现（YouTube、NHK 已修到 1 秒内）；切换翻译模式或引擎后已翻译页面自动重翻。

## PDF
- 版式保持的双栏对照：右侧是与原页同尺寸的译文页，译文覆盖在原文块位置上，公式、图片、页眉页脚保持原样；另有「仅译文页」「原文页」「重排阅读」三种视图。
- 作者、机构、邮箱行不翻译；先显示机器翻译草稿，再换成大模型终稿。

## 本机网关（可选）
- 新虚拟模型 `auto`：在交大、Hermes 免费模型与本机 Ollama 之间按健康度和速度选择，永不使用 claude/codex 订阅；并发满时排队而不是立即 503；交大本地令牌桶；分阶段超时；`/health` 显示各后端状态。
- 「一键接入本机网关」默认模型改为 `auto`。

## 已知限制
- 自动化验收（`tests/e2e/run_acceptance.py`，桌面/暗色/手机/平板触屏模拟）仍有未通过项：部分站点覆盖率口径、少量排版候选，以及恢复原文后的严格 DOM 比对差异（已确认无扩展残留属性，尚未全部归因）。Stack Overflow、Reddit、X、eBay 会拦截自动化浏览器，未纳入自动验收。
- 手机/平板结果来自触屏模拟，不能替代 Android Edge + Tampermonkey 真机；PDF 阅读器仍只在桌面扩展中提供。
- 漫画 OCR 对竖排手写字体仍会误识别；机器翻译草稿的语义质量有限，大模型精修后改善。
